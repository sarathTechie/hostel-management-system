The additive migrations `20261018010000_admin_workflow_metadata` and `20261018190000_in_app_notifications` add workflow metadata and a notification table. Applying the new notification migration does not reset or reseed the database or alter existing business records. Generated Prisma client files are ignored and regenerated by `npm run db:generate`.

The SRS-level items below are not supplied by the application code and remain deployment or policy work: configure and verify the daily PostgreSQL backup/30-day backup retention schedule, HTTPS termination and restore procedure; run the specified concurrency/latency/availability tests; define and enforce the two-year student/fee/complaint data-retention policy; and configure any external email/SMS/push delivery. In-app leave notifications are implemented; external delivery is not configured. The SRS does not define permissions for a separate System Administrator or mess in-charge business role, so the app retains its three defined account roles until those permissions are approved. Automatic data deletion remains disabled.

## Cross-cutting requirements

- The project prompt also requires React/TypeScript, Express/TypeScript, Prisma/PostgreSQL, secure cookies, Argon2id, validation, rate limits, database transactions, repeatable fictional seed data and developer documentation. Implementations are in `client/`, `server/` and the docs in this directory.
- The SRS's quantitative performance constraints and the project prompt's 300-user target are not verified. See `docs/TESTING.md`.
- The remaining material gaps are database-backed integration tests, notification delivery, room/visitor/report filter acceptance with real data, and any institutional policies that remain TBD.
